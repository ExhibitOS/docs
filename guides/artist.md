# 작가: 원본을 보존하고 검토한 작품을 전시에 전달하기

관리자가 준비한 서버의 `/cms`에서 본인 계정으로 로그인합니다. 로그인 계정과 작가 프로필은 별개입니다. 작가 프로필을 만들고 본인 작품을 등록합니다. 큐레이터에게 원본 업로드나 작가 편집 권한이 자동으로 생기지는 않습니다.

1. 제목·원문 설명·실측 치수를 입력합니다. 치수 단위는 미터이며 파일의 좌표를 자동으로 맞추는 값이 아닙니다. 원래 단위와 실제 적용한 변환을 기록하고 모르는 연도·재료는 비워 둡니다.
2. 저작권자·라이선스·credit·유효 기간과 display/download/export 각각의 허용 여부를 검토합니다. 코드의 오픈소스 라이선스가 작품 권리를 대신하지 않습니다.
3. 원본은 따로 보관한 채 현재 지원되는 GLB/PNG 사본을 import합니다. 업로드 hash/크기와 job 상태를 확인합니다. `approved`는 파일 형식 검사 결과이며 작품의 공개 승인이 아닙니다. 지원되지 않는 파일은 원본을 수정해 억지로 통과시키지 않습니다.
4. 현재 작품 revision과 선택 asset을 함께 검토·승인합니다. metadata를 바꾸면 이전 승인이 해제되므로 다시 검토합니다. 충돌 메시지가 나오면 최신 revision을 읽고 변경을 비교합니다.
5. 큐레이터는 승인된 display 사본을 전시 초안에 넣습니다. 원본 다운로드와 OEX export는 독립 권한이며 display 허용만으로 실행할 수 없습니다.

[기본 import](../artist/import.md)와 [CMS 조작](../artist/cms.md)은 초기 단계 설명입니다. 현재 파일 지원·제한의 기준은 [현재 Platform CMS](https://github.com/ExhibitOS/platform/blob/6663912e4cdaf205cbc648551f4a0bb55b6f0293/docs/cms.md)와 [import](https://github.com/ExhibitOS/platform/blob/6663912e4cdaf205cbc648551f4a0bb55b6f0293/docs/imports.md)입니다. 일반 glTF 전체 또는 모든 색 공간을 지원한다고 가정하지 마세요.

## 글 제안과 번역 검토

CMS의 글 제안에서는 원문과 제안문이 따로 표시됩니다. human/local-ai/external-ai 출처, 도구·버전과 원문 hash를 확인한 뒤 직접 수락 또는 거절합니다. metadata 제안은 수락만으로 반영되지 않으며 **반영**을 별도로 선택합니다. 새 revision은 다시 작품 승인을 받아야 하고 자동 공개되지 않습니다. 번역은 원문과 분리된 검토 기록이며 자동으로 공개 전시 번역에 삽입되지 않습니다. 외부 AI 항목은 명명된 제공자와 명시적 동의가 필요한 준비 기록일 뿐, 현재 제품이 제공자에 원문을 전송하거나 번역을 생성한 것이 아닙니다.

## 보존 상태와 개인 정보

보존 보기의 hash/누락 경고는 기술적 상태이며 예술적 평가가 아닙니다. 누락·불일치를 확인하면 원본 사본과 기록을 보존하고 운영자에게 알립니다. 보존 표시만으로 backup/restore가 완료된 것이 아닙니다. 본인 metadata 내보내기와 계정 처리에는 [개인정보 안내](privacy.md)를 사용합니다. 실제 촬영의 색·실측·품질과 기기별 qualification은 별도이며 문서나 합성 검사로 통과했다고 볼 수 없습니다.
