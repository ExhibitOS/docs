# Studio 로컬 초안과 복원

Studio 개발판의 `/studio`는 계정 없이 전시 문서의 로컬 초안을 만들고,
JSON을 편집·자동 저장하며 이력과 파일 백업으로 복원하는 화면이다.
공간을 직접 조작하는 3D 편집기, 작품 Viewer와 publication은 후속 기능이다.
실행 명령과 검사 환경은 [Platform README](https://github.com/ExhibitOS/platform#readme),
API와 저장 형식은 [Studio 안내](https://github.com/ExhibitOS/platform/blob/main/docs/studio.md)를 따른다.

## 오프라인 작업 준비

먼저 연결된 상태에서 production 웹의 `/studio`를 열고 오프라인 앱 준비가
완료됐는지 확인한다. 이 과정은 공개 앱 코드를 저장한다. 이후 같은 브라우저
프로필과 origin에서 연결을 끊고 `/studio`를 다시 열 수 있다. 최초 설치를
오프라인에서 할 수는 없으며 Vite development 서버는 이 보장을 제공하지 않는다.

‘새 로컬 전시’를 누르면 계정이나 서버 요청 없이 draft를 만든다. 제목과 전시
문서 JSON을 편집하면 유효한 문서만 자동 저장된다. 공간 치수, 표면·개구부,
작품 배치·transform, navigation·accessibility와 작품 snapshot을 문서에 보존한다.
단위는 meter, 좌표계는 right-handed Y-up이며 현재 규격은 `1.0.0-draft.1`이다.
잘못된 구조·참조·단위·quaternion 등은 거부하고 마지막 완료된 저장본을 유지한다.
작품 파일 bytes는 이 단계에서 가져오거나 검증하지 않는다. 편집 입력은 UTF-8
1,000,000 bytes, 서버 전체 요청은 wrapper 포함 1 MiB 한도다. 공개 규격의
문서 한도에 가까운 JSON도 입력·요청 한도 때문에 거부될 수 있다.

## 저장 실패와 이력 복원

다른 탭이 먼저 저장하면 현재 입력과 최신 저장본을 비교하고 새 사본을 만든다.
충돌한 입력으로 최신 기록을 자동 덮어쓰지 않는다. 이전 이력의 복구는 새로운
version을 추가하며 기존 이력을 유지한다. 화면에는 최신 50개 이력을 표시하며 더 오래된
이력도 저장소에 남고 원문 구조 백업에 포함된다. 사본은 새 draft·exhibition·revision ID를
사용하고 서버 계정 연결을 제거한다.

Quota 부족, 중단된 저장, 손상된 기록이나 새 버전 기록의 오류를 보면 현재 입력을
파일로 백업한다. 저장본·현재 입력 백업은 정상 저장본 JSON과 미저장 입력 text를
별도로 다운로드한다. 브라우저 저장 공간을 정리하기 전에 실제 다운로드 파일을
확인한다. 브라우저 데이터 삭제·eviction·기기 장애는 이력까지 없앨 수 있다.
이 구현은 draft나 이력, 이전 앱 캐시를 자동 삭제하지 않는다.

형식 1의 정상 기록은 형식 2로 이동하며 원문을 남긴다. 다른 탭이 업그레이드를
막으면 해당 탭을 닫고 ‘저장소 다시 읽기’로 재시도한다. 손상·미래 형식은 덮어쓰지
않는다. ‘원문 구조 백업’은 진단용 raw JSON이며 정상 백업 import 파일과 다르다.

정상 JSON 백업을 복원하면 유효성을 검사한 뒤 새로운 독립 사본을 만든다.
기존 기록을 대체하지 않는다. 백업은 문서 metadata이며 작품 파일, 자격정보나
전체 OEX 패키지를 포함하지 않는다. 작품 파일은 별도로 백업해야 한다.

## 선택적 서버 저장

[Artist CMS](cms.md)에서 로그인한 뒤 Studio에서 현재 서버 계정을 명시적으로
확인한다. 로그인이나 온라인 전환만으로 초안을 서버에 전송하지 않는다.
Artist·curator는 자신의 초안을 관리하며 admin은 같은 기관의 초안을 관리한다.
다른 소유자·기관·viewer에게 private authoring 접근을 허용하지 않는다.

서버 저장은 강한 ETag와 현재 계정·기관 권한을 확인한다. 다른 편집으로 서버가
바뀌면 412 충돌을 표시하고 입력을 보존한다. 서버 내용을 비교한 뒤 명시적으로
로컬에 적용하거나 현재 입력을 비교한 서버에 적용하거나 별도 사본을 만든다.
비교 후 서버가 다시 바뀌면 새 적용도 거부한다.

응답이 유실된 요청의 정확한 재시도는 기존 revision을 반환한다. 이 값이 최신
서버 상태라는 뜻은 아니므로 이후 적용 전에 현재 서버 내용을 비교한다.
재시도 intent는 현재 화면 memory에 있다. 다시 연 뒤에는 서버 내용을 읽어
비교하고 명시적으로 이어간다. 연결된 draft와 현재 계정이 다르면 동기화를 막는다.

로컬 초안은 브라우저 프로필·origin 단위이며 로그아웃 후에도 남는다. 공유
브라우저에서 계정별로 격리된 비밀 저장소가 아니다. private 로컬 작업은 별도
브라우저 또는 OS 프로필을 사용한다. Offline worker는 API·인증·draft 응답을
캐시하지 않으며 서버는 매 요청의 현재 권한을 검사한다.

새 앱 버전은 명시적인 적용 또는 이전 탭이 닫힌 뒤 활성화된다. 적용 전에
파일 백업을 보관한다. 앱 코드의 캐시 성공과 초안의 장기 보존은 별개다.
