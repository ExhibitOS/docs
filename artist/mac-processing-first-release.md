# 1차 출시: iPhone에서 촬영하고 Mac에서 완성하기

2026-10-15 사용자가 확정한 제품 방향입니다. 구현 대상과 실제 검증 완료는 구분합니다.

1. iPhone에서 촬영·품질 안내를 확인하고 원본을 보관합니다. 선택적인 `.reduced`는 빠른 촬영 확인이며 최종 승인이 아닙니다.
2. Capture의 “전체 원본 공유”로 원본 폴더가 담긴 ZIP을 Mac에 전달하고 압축을 풉니다. 사진과 촬영 정보·권리·출처를 포함한 폴더 구조를 유지하며, 미리보기 모델을 원본 대신 사용하지 않습니다.
3. Mac Swift·RealityKit Processing에서 원본을 재구성합니다. 지원되는 상세 수준을 선택하고 진행·실패·취소·재시도를 확인합니다. 높은 상세 수준이 잘못 찍힌 부분을 복구한다고 가정하지 않습니다.
4. 실제 내보낼 GLB와 LOD를 회전·확대해 형상·표면·치수를 검토합니다. 생성 성공은 품질/공개 승인이 아닙니다. 원본 master와 파생본은 구분해 보존합니다.
5. GLB·LOD·OES를 내보내 Mac Studio/CMS에서 작품을 등록·검토·승인하고 전시를 공개합니다. Mac Manager가 설치·실행·백업·복원·업데이트·롤백을 담당합니다.

촬영·Mac 처리·파일 내보내기는 서버/클라우드 계정 없이 로컬에서 완료하는 경로입니다. 외부 업로드는 별도 선택과 권한 검사를 거칩니다. 기존 암호화 자료·키·원본·완료 결과는 새 경로 검증 전 삭제하지 않습니다.

Viewer 구현 대상은 Safari·Chrome이고 공식 검증 환경은 macOS/iOS입니다. 각 실제 검사 전 지원 완료로 표시하지 않습니다. Windows/Linux Chrome은 호환 후보이며 Mac Chrome 검사로 입증하지 않습니다. 인터넷 공개는 Cloudflare Pages 정적 단독과 선택적 Render 동적 서버·Render PostgreSQL을 사용합니다. Ubuntu 직접 배포와 Railway는 후속 보류이며 사용자 앱의 OS 지원과 서버 운영 환경은 구분합니다.

Windows/Linux native Manager·Processing, Android Capture, iPhone 최종 Processing, Node 재구성, 다중 cloud/범용 원격 배포, AR/XR/Federation/기관 고급 연동은 후속 보류입니다. Node의 기존 검사·출력·백업 도구는 재사용할 수 있습니다.

## 설치와 호환 도구

Capture와 Mac Processing은 선택적 기본 도구입니다. 두 앱 없이도 [현재 지원 작품 파일](import.md)을 Platform·Studio에 가져올 수 있습니다. 공식 앱 설치·계정·서명·App Store 영수증을 작품 수용 조건으로 삼지 않으며 같은 무결성·권리·품질 검토를 적용합니다.

정식 Manager는 Developer ID 서명·Apple 공증 후 웹사이트에서, 공식 Mac Processing은 Mac App Store에서 배포·업데이트하는 방향입니다. 현재 공식 다운로드·스토어 페이지는 준비 중입니다. Capture도 일반 사용자 설치 경로가 아직 제공되지 않습니다. 개발·시험 앱 실행과 정식 배포 완료를 구분합니다.

### 사용 순서와 확인

1. Capture에서 새 촬영이나 기존 기록을 열고 안내에 따라 촬영합니다. 흔들림·추적 문제는 필요한 멈춤·재촬영 안내를 따르고 원본 보존과 처리 입력 제외를 구분합니다.
2. 기록을 보관한 뒤 아래 [원본 공유와 Mac에서 열기](#원본-공유와-mac에서-열기)를 따라 전달합니다. 저장 완료와 선택적 빠른 미리보기 완료는 최종 모델 승인이 아닙니다.
3. Mac Processing에서 촬영 파일을 가져오거나 기존 작업을 엽니다. 입력 확인·실제 처리·실패·취소 상태를 확인합니다. 지원되지 않는 재개를 가정하지 않습니다.
4. 실제 모델을 회전·확대해 구멍·형상·바닥·색·치수를 검토합니다. 지원되는 수정은 원본을 보존한 파생 결과로 만들고 다시 검토합니다.
5. Studio용 결과를 내보내고 저장 위치·파일 검증 결과를 확인합니다. Manager·Studio가 없어도 파일 내보내기는 독립적입니다.

### 원본 공유와 Mac에서 열기

이 단계에서는 촬영 원본을 전달합니다. 최종 모델 생성이나 품질 승인은 아직 수행하지 않습니다.

1. Capture의 “Mac으로 원본 보내기”에서 보낼 촬영 기록을 고릅니다. 원본을 내보낼 권리와 선택한 대상에게 전달할 동의를 확인한 뒤 “전체 원본 공유”를 누릅니다.
2. 원본 사본 복사·확인과 ZIP 압축이 끝나 공유 화면이 열릴 때까지 기다립니다. 화면의 퍼센트는 표시된 복사 또는 압축 단계의 진행이며, 전체 작업의 남은 시간을 뜻하지 않습니다. 마무리 등 진행률을 알 수 없는 단계에는 단계 안내와 경과 시간이 표시됩니다.
3. 공유 화면에서 AirDrop으로 Mac에 보내거나 “파일에 저장”을 선택합니다. 파일에 저장했다면 그 ZIP을 Mac에서 접근할 수 있는 위치로 옮깁니다. 공유를 취소해도 iPhone 원본은 남으며 다시 공유할 수 있습니다.
4. Mac의 Finder에서 받은 `ExhibitOS-originals-촬영기록ID.zip`을 이중 클릭해 압축을 풉니다. 안의 `mac-input-…` 원본 폴더 전체를 유지합니다. 그 폴더에는 `mac-input.json`과 사진·촬영 정보가 함께 있습니다. ZIP 바깥의 보관 폴더가 한 겹 더 보이면 안으로 들어가 이 원본 폴더를 찾습니다. 사진만 따로 옮기거나 파일 이름·구조를 바꾸지 않습니다.
5. Mac Processing에서 “촬영 파일 가져오기”를 누르고 압축을 푼 `mac-input-…` 폴더를 선택한 뒤 “원본 가져오기”를 누릅니다. 현재 파일 선택창은 **폴더만** 받으므로 ZIP 자체나 그 안의 개별 사진·JSON 파일을 선택하지 않습니다. “저장 모델 열기”는 이미 만든 모델 결과를 여는 기능이므로 이 단계에서 사용하지 않습니다.

선택한 원본 이름이 화면에 표시되는지 확인합니다. Apple 촬영 원본은 “사진 확인”에서 저장된 사진과 이번 처리에 사용할 사진을 확인한 뒤 모델 만들기로 이어갑니다. 파일 선택창에서 취소하면 새 원본을 불러오지 않고 현재 화면으로 돌아갑니다. 열리지 않으면 ZIP 압축을 풀었는지, 사진만 있는 하위 폴더 대신 촬영 정보가 함께 든 원본 폴더를 선택했는지 확인합니다. 접근 오류가 표시되면 해당 폴더를 다시 선택하되 원본이나 이전 결과를 삭제하지 않습니다.

처리 실패 시 원본·이전 완료 결과를 지우지 말고 입력·메모리·공간·권한 안내를 확인합니다. 높은 상세 수준이나 생성 성공만으로 실제 작품 품질·실측·공개 승인을 대신하지 않습니다.
