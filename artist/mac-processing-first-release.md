# 1차 출시: ExhibitOS Capture 촬영 → ExhibitOS Processing GLB → Studio 작품 생성

2026-10-21 최신 역할 결정입니다. Processing은 ExhibitOS Capture 촬영본 처리·모델 확인·GLB 저장만 담당합니다. Studio는 외부 도구의 지원 GLB로도 작품을 만들고 정보·권한·출처·전시·OEX 내보내기를 관리합니다. 구현 대상과 실제 UI/검증 완료는 구분합니다.

1. iPhone에서 촬영·품질 안내를 확인하고 원본을 보관합니다. 선택적인 `.reduced`는 빠른 촬영 확인이며 최종 승인이 아닙니다.
2. Capture의 “전체 원본 공유”로 원본 폴더가 담긴 ZIP을 Mac에 전달하고 압축을 풉니다. 사진과 촬영 정보·권리·출처를 포함한 폴더 구조를 유지하며, 미리보기 모델을 원본 대신 사용하지 않습니다.
3. Mac Swift·RealityKit Processing에서 원본을 재구성합니다. 지원되는 상세 수준을 선택하고 진행·실패·취소·재시도를 확인합니다. 높은 상세 수준이 잘못 찍힌 부분을 복구한다고 가정하지 않습니다.
4. 실제 내보낼 GLB를 회전·확대해 형상·표면·치수를 검토합니다. LOD를 생성·사용한다면 해당 사본도 검토합니다. 생성 성공은 품질/공개 승인이 아닙니다. 원본 master와 파생본은 구분해 보존합니다.
5. 검토한 `.glb`를 저장하고 Studio/CMS에서 작품을 만든 뒤 파일을 업로드합니다. 제목·작가·실측 치수·권한·출처를 Studio에서 입력하고 검토하며, 전시 편집 후 OEX 내보내기 또는 별도 승인된 공개를 진행합니다. Mac Manager가 설치·실행·백업·복원·업데이트·롤백을 담당합니다.

촬영·Mac 처리·파일 내보내기는 서버/클라우드 계정 없이 로컬에서 완료하는 경로입니다. 외부 업로드는 별도 선택과 권한 검사를 거칩니다. 기존 암호화 자료·키·원본·완료 결과는 새 경로 검증 전 삭제하지 않습니다.

Viewer 구현 대상은 Safari·Chrome이고 공식 검증 환경은 macOS/iOS입니다. 각 실제 검사 전 지원 완료로 표시하지 않습니다. Windows/Linux Chrome은 호환 후보이며 Mac Chrome 검사로 입증하지 않습니다. 인터넷 공개는 Cloudflare Pages 정적 단독과 선택적 Render 동적 서버·Render PostgreSQL을 사용합니다. Ubuntu 직접 배포와 Railway는 후속 보류이며 사용자 앱의 OS 지원과 서버 운영 환경은 구분합니다.

Windows/Linux native Manager·Processing, Android Capture, iPhone 최종 Processing, Node 재구성, 다중 cloud/범용 원격 배포, AR/XR/Federation/기관 고급 연동은 후속 보류입니다. Node의 기존 검사·출력·백업 도구는 재사용할 수 있습니다.

## 모델 중심 작업실과 개발 중인 표면 정리

개발판 작업실에서는 모델을 중심으로 대상 목록·속성·필요한 UV/사진/비교/이력을 여는 배치와 일반·전문가 모드를 한정된 실제 화면에서 확인했습니다. 모든 키보드 메뉴 조작·최소 화면 크기·접근성 확인이나 정식 배포가 완료된 것은 아닙니다. 두 모드는 같은 프로젝트·선택·카메라·미저장 편집·이력을 공유하며, 전문가는 일반의 쉬운 작업 경로에 상세 설정을 더합니다. 일반 화면에 표시할 수 없는 상세 값을 모드 전환만으로 초기화하지 않는 원칙은 변경 경로별로 확인합니다.

표면 정리는 기본 **요철 줄이기**와 명시적 **평면으로 맞추기**, 같은 편집 경로의 정리 브러시를 구분하는 개발 범위입니다. 곡면 정리의 선택·미리보기·명시적 취소는 일부 확인했지만 화면 갱신·Esc 취소 문제가 남았고, 해당 변경의 적용·프로젝트 재열기·GLB 출력과 소비는 아직 확인하지 않았습니다. 새 기능 전체 제공·실제 스캔 품질·정확한 원형 복원이 입증된 것으로 안내하지 않습니다. 기존 원본·프로젝트·GLB와 이전 버전의 검증 범위는 보존합니다.

## 개발판에서 편집 결과 보관하기

기존 개발판에서 색·텍스처·PBR, UV·부분 재질 편집과 적용·이력·프로젝트 다시 열기, 일반 GLB 출력의 한정된 실제 확인이 있습니다. 원본과 편집 프로젝트를 보관하고 적용한 결과를 다시 열어 비교하세요. UV 공유 출력은 갱신된 reader가 필요하므로 이전 앱으로 새 공유 출력을 읽을 수 있다고 가정하지 않습니다. 이 확인은 모든 작품의 형상·실측·색 정확도나 현재 네이티브 Studio 전체 수락을 뜻하지 않습니다.

최신 로컬 개발 패키지 생성과 정식 설치·실행은 [현재 제공 상태](../status.md)에서 구분합니다. 원본·EXCP 전달은 최종 재구성 품질 승인이 아니며, 처리 실패·취소 시 이전 결과를 삭제하지 않습니다. 외부 도구의 일반 GLB도 같은 검토를 거쳐 독립적으로 사용할 수 있습니다.

## 설치와 호환 도구

Capture와 ExhibitOS Processing은 선택적 기본 도구입니다. 두 앱 없이도 [현재 지원 작품 파일](import.md)을 Platform·Studio에 가져올 수 있습니다. 공식 앱 설치·계정·서명·App Store 영수증을 작품 수용 조건으로 삼지 않으며 같은 무결성·권리·품질 검토를 적용합니다.

정식 Manager는 Developer ID 서명·Apple 공증 후 웹사이트에서, 공식 ExhibitOS Processing은 Mac App Store에서 배포·업데이트하는 방향입니다. 현재 공식 다운로드·스토어 페이지는 준비 중입니다. Capture도 일반 사용자 설치 경로가 아직 제공되지 않습니다. 개발·시험 앱 실행과 정식 배포 완료를 구분합니다.

### 사용 순서와 확인

1. Capture에서 새 촬영이나 기존 기록을 열고 안내에 따라 촬영합니다. 흔들림·추적 문제는 필요한 멈춤·재촬영 안내를 따르고 원본 보존과 처리 입력 제외를 구분합니다.
2. 기록을 보관한 뒤 아래 [원본 공유와 Mac에서 열기](#원본-공유와-mac에서-열기)를 따라 전달합니다. 저장 완료와 선택적 빠른 미리보기 완료는 최종 모델 승인이 아닙니다.
3. ExhibitOS Processing에서 촬영 파일을 가져오거나 기존 작업을 엽니다. 입력 확인·실제 처리·실패·취소 상태를 확인합니다. 지원되지 않는 재개를 가정하지 않습니다.
4. 실제 모델을 회전·확대해 구멍·형상·바닥·색·치수를 검토합니다. 지원되는 수정은 원본을 보존한 파생 결과로 만들고 다시 검토합니다.
5. Studio용 결과를 내보내고 저장 위치·파일 검증 결과를 확인합니다. Manager·Studio가 없어도 파일 내보내기는 독립적입니다.

### 원본 공유와 Mac에서 열기

이 단계에서는 촬영 원본을 전달합니다. 최종 모델 생성이나 품질 승인은 아직 수행하지 않습니다.

1. Capture의 “Mac으로 원본 보내기”에서 보낼 촬영 기록을 고릅니다. 원본을 내보낼 권리와 선택한 대상에게 전달할 동의를 확인한 뒤 “전체 원본 공유”를 누릅니다.
2. 원본 사본 복사·확인과 ZIP 압축이 끝나 공유 화면이 열릴 때까지 기다립니다. 화면의 퍼센트는 표시된 복사 또는 압축 단계의 진행이며, 전체 작업의 남은 시간을 뜻하지 않습니다. 마무리 등 진행률을 알 수 없는 단계에는 단계 안내와 경과 시간이 표시됩니다.
3. 공유 화면에서 AirDrop으로 Mac에 보내거나 “파일에 저장”을 선택합니다. 파일에 저장했다면 그 ZIP을 Mac에서 접근할 수 있는 위치로 옮깁니다. 공유를 취소해도 iPhone 원본은 남으며 다시 공유할 수 있습니다.
4. Mac의 Finder에서 받은 `ExhibitOS-originals-촬영기록ID.zip`을 이중 클릭해 압축을 풉니다. 안의 `mac-input-…` 원본 폴더 전체를 유지합니다. 그 폴더에는 `mac-input.json`과 사진·촬영 정보가 함께 있습니다. ZIP 바깥의 보관 폴더가 한 겹 더 보이면 안으로 들어가 이 원본 폴더를 찾습니다. 사진만 따로 옮기거나 파일 이름·구조를 바꾸지 않습니다.
5. ExhibitOS Processing에서 “촬영 파일 가져오기”를 누르고 압축을 푼 `mac-input-…` 폴더를 선택한 뒤 “원본 가져오기”를 누릅니다. 현재 파일 선택창은 **폴더만** 받으므로 ZIP 자체나 그 안의 개별 사진·JSON 파일을 선택하지 않습니다. “저장 모델 열기”는 이미 만든 모델 결과를 여는 기능이므로 이 단계에서 사용하지 않습니다.

선택한 원본 이름이 화면에 표시되는지 확인합니다. Apple 촬영 원본은 “사진 확인”에서 저장된 사진과 이번 처리에 사용할 사진을 확인한 뒤 모델 만들기로 이어갑니다. 파일 선택창에서 취소하면 새 원본을 불러오지 않고 현재 화면으로 돌아갑니다. 열리지 않으면 ZIP 압축을 풀었는지, 사진만 있는 하위 폴더 대신 촬영 정보가 함께 든 원본 폴더를 선택했는지 확인합니다. 접근 오류가 표시되면 해당 폴더를 다시 선택하되 원본이나 이전 결과를 삭제하지 않습니다.

처리 실패 시 원본·이전 완료 결과를 지우지 말고 입력·메모리·공간·권한 안내를 확인합니다. 높은 상세 수준이나 생성 성공만으로 실제 작품 품질·실측·공개 승인을 대신하지 않습니다.

### 검토한 GLB로 Studio 작품 만들기

1. Processing에서 실제 저장할 모델을 확인하고 검토·내보내기 권리를 확인합니다.
2. 기존 GLB 저장 기능으로 `.glb`를 새 위치에 저장합니다. 이전 개발판에서는 “다른 형식·저장 위치” 아래에 있습니다. OES/OEX 포장은 필요하지 않습니다.
3. Studio/CMS에서 작가·비공개 작품을 만들고 [GLB 업로드](import.md)를 진행합니다. 현재 UI는 작품 생성 후 파일 등록 순서입니다.
4. 제목·작가·실측 치수·권한·사용자가 확인한 출처를 Studio에서 입력·검토합니다. 파일 검사 통과를 품질/공개 승인으로 취급하지 않습니다.
5. 작품을 전시에 배치·저장하고 필요하면 Studio에서 OEX를 내보냅니다. 외부 촬영/모델링 GLB도 3번부터 같은 절차를 사용합니다.

GLB만으로 원본 촬영 이력이 자동 전송되지는 않습니다. Processing 내부 기록·원본은 보존하며, 외부 GLB에 ExhibitOS Capture 이력이나 별도 파일을 강제하지 않습니다. 실제 지원 GLB 제한은 [현재 Platform 안내](https://github.com/ExhibitOS/platform/blob/main/docs/imports.md)를 따릅니다.

### 이전 개발판의 OEX 전달 절차 — 호환·이력 참고

아래는 기존 구현과 증거를 보존한 설명이며 새 기본 흐름이 아닙니다. 이 문서 수정은 기존 버튼 제거·새 UI 검증 완료를 뜻하지 않습니다. 기존 개발판에 구현된 파일 전달 절차입니다. 공식 배포나 실제 작품의 품질·공개 승인이 완료됐다는 뜻은 아닙니다.

1. Processing에서 기본 모델을 회전·확대해 형상·색·크기를 확인하고 검토 확인을 켭니다. 가벼운 사본을 만들었다면 그 사본도 표시해 검토 확인을 켠 뒤 **기본 모델로 돌아옵니다**. “이 모델을 내보낼 권리가 있습니다”도 확인합니다. 작업 중이거나 출력 크기가 지원 범위를 넘으면 안내에 따라 해결한 뒤 진행합니다.
2. “Studio로 가져갈 파일 저장…”을 누릅니다. “새 작품 정보”에 제목·작가·저작 형태, 현재 모델 축과 같은 방향으로 직접 측정한 가로 X·높이 Y·깊이 Z(mm), 권리자·권한 근거·이용 허락 조건을 입력합니다. 실측 값 입력은 모델을 자동으로 확대하거나 형상을 보정하지 않습니다. “이 모델의 파일 내보내기를 허락합니다 · 필수”를 확인하고, 추가 이용 허락은 실제 허락된 항목만 선택합니다. 기존 작품 정보를 유지하려면 “기존 작품 파일 사용”으로 `artwork.json`과 작품 파일이 함께 있는 폴더를 선택합니다.
3. 새 정보를 입력했다면 “정보 확인 후 저장 위치 선택”을 누르고, 이름 끝이 `.oex`인 새 파일로 저장합니다. 저장 위치 선택을 취소하면 전달 파일을 저장하지 않으며 원본·기존 결과는 유지됩니다. 저장이 끝나면 Finder에서 선택된 파일 위치를 확인합니다. GLB나 OES가 필요하면 “다른 형식·저장 위치”를 펼칩니다.
4. Studio에서 artist 또는 admin 계정으로 로그인하고 **전시 OEX 파일**의 “OEX 가져오기 파일”에서 저장한 `.oex`를 선택합니다. “파일 전달·가져오기 시작”을 누르고 상태를 확인한 뒤, 완료되면 “가져온 전시 열기”를 누릅니다. 현재 편집 중인 미저장 입력이 있으면 먼저 저장합니다.

이 경로는 작품이 담긴 **새 비공개 전시 초안**을 만들며 배치는 직접 해야 합니다. 기존 전시에 작품을 넣는 “승인된 CMS 작품 가져오기”와는 다른 경로입니다. 파일 저장·가져오기가 인터넷 공개를 수행하지 않으므로 전시 검토와 공개 준비·승인은 별도로 진행합니다.
